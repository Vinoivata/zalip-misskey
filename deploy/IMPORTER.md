# Импортёр контента Zalip

Это серверное расширение текущего Misskey, а не клиентский AiScript-плагин.
Панель администратора: `/zalip/importer` (также ссылка из редактора контента).
Публичные справочники: `/zalip/taxonomy`, страницы создателей/студий/жанров/
категорий/подборок: `/zalip/taxonomy/:type/:slug`.

## Второй этап — повторный аудит DLE Movie Importer Pro 2.1.3

Это адаптация функций к Misskey, не исполнение или копирование закрытого PHP-модуля.
Исходный архив проверен: SHA256
`A15FB12AEC08021E685125EF76182126A4D0497286F573F454CB1C75271D7911`.

- Запуск/профиль хранит выбранные источники, поля, источник каждого поля и фильтры:
  тип, годы, жанры, страны, минимальная внешняя оценка. Неподходящий тайтл
  пропускается без записи. Первичный источник всегда участвует; по умолчанию
  официальная оценка Кинопоиска приоритетнее кешированной оценки плеера.
- Отключение создателей/сезонов исключает дополнительные запросы TMDB/Кинопоиска.
- IMDb `tt…` и ссылки IMDb сопоставляются точно внутри очереди выбранным TMDB,
  Кинопоиском или Collaps. Нет массового разрешения ID запросами из браузера.
- Запасной сохранённый ID применяется только при not-found первичного источника,
  не при ошибке авторизации/квоты/транспорта или конфликте идентичности.
- Постоянные блокировки тайтла можно заменить точным набором. Редактор показывает
  источник и ручное владение. Снятие блокировки не стирает ручное значение.
- Можно явно проверить подключение каждого API. Результат кешируется 5 минут,
  запрос Кинопоиска входит в суточный бюджет. Открытие панели не запускает проверку.
- Изображения по умолчанию удалённые. Опция локального WebP сохраняет оригинал и
  уменьшенную копию в штатном Drive, только с известных CDN, без редиректов и
  секретных URL, с лимитами тела/декодирования. Ручные картинки не заменяются.
  Неудачное обновление сохраняет рабочее изображение; новый тайтл получает remote
  fallback с предупреждением. Галерея обновляется атомарно, до 12 кадров за элемент.
- Создатель явно обогащается по сохранённому TMDB/Кинопоиск ID: биография, даты,
  место рождения, псевдонимы, исходное имя, фото и IMDb `nm…`. Каждый ключ защищён
  отдельно, включая намеренное очищение; совпадение по имени не объединяет людей.
- Явный пересчёт категории ограничен 100 тайтлами/запрос и имеет курсор. Меняются
  только её связи `rules`, ручные связи и блокировки сохраняются.
- Профиль можно включить/выключить, удалить, сбросить курсор. Активный запуск
  блокирует удаление/сброс/смену источника. Выключение запрещает следующий запуск,
  но не отменяет текущий. Исправлены границы формы/БД: имя 120, ID коллекции 100.
- Поток новинок Collaps дополняет обход коллекций. Все новые тайтлы — черновики.
- Диагностика подписок/outbox показывает только агрегаты. Ожидание не означает
  подтверждённый сбой; загрузка статистики не инициирует отправку уведомлений.

Новая добавочная миграция: `1791748291148-ZalipImporterOptions.js` (JSONB options
у заданий и профилей, безопасные warnings у элементов журнала). Предупреждения
видны после завершения задания; URL, ключи и сырой текст провайдера не сохраняются.
Down удаляет эти параметры и отключает discovery-профили;
на production down автоматически не выполняется.

Оставшиеся отличия от DLE: словарь подборок Collaps с полным возобновляемым
backfill/зеркальной очисткой, семантические виды подборок и части франшиз,
объединение персон с редиректами, отдельный cron их обогащения, пагинация публичной
фильмографии и настройки названий/порядка плееров. AI/SEO/переводы и YouTube-поиск
трейлеров исключены по решению владельца: текущий объём — только четыре источника.
Лицензирование,
TPL/xfields/XML и автопубликация DLE не переносятся; автопубликация противоречит
согласованной политике черновиков. Это не заявление о полном паритете с DLE.

## Подключение источников

Ключи хранятся вне Git в закрытом серверном env-файле. `compose.release.yml`
передаёт их только серверу. Для каждого источника нужна своя переменная:

| Переменная | Назначение |
| --- | --- |
| `ZALIP_TMDB_API_KEY` | TMDB v3: поиск, метаданные, изображения, создатели, сезоны/серии |
| `ZALIP_KINOPOISK_API_KEY` | Kinopoisk API Unofficial: поиск, русские метаданные, рейтинги, создатели |
| `ZALIP_ALLOHA_API_TOKEN` | Alloha v2: сопоставление по TMDB, доступность и плеер |
| `ZALIP_COLLAPS_API_TOKEN` | Collaps: поиск, карточки, коллекции, доступность и плеер |
| `ZALIP_KINOPOISK_DAILY_BUDGET` | Локальный общий лимит запросов Кинопоиска в сутки; по умолчанию 350 |
| `ZALIP_ALLOHA_IFRAME_HOSTS` | Необязательный список точных разрешённых доменов iframe через запятую |
| `ZALIP_COLLAPS_IFRAME_HOSTS` | То же для Collaps |

Статус «настроен» означает наличие серверного ключа, не успешную проверку доступа.
Ненастроенный источник пропускается при дополнении данных. Alloha не использует
неподтверждённый поиск по названию: доступны TMDB-ссылки вида `tmdb:tv:123` или
`tmdb:movie:123`. Ключи не возвращаются в API и не входят в задания/журналы.
IFrame может содержать публичный идентификатор доступа, предусмотренный провайдером;
серверный API-ключ в браузер не передаётся. Не добавляйте произвольные домены в allowlist.
Во время проверки Alloha вернул iframe с параметром `token`, совпадающим с серверным
API-ключом. Импортёр намеренно отклоняет такой плеер (`alloha-player-url-rejected`),
но сохраняет безопасные метаданные. Для нового плеера Alloha требуется отдельная
browser-safe ссылка/идентификатор от провайдера; существующая legacy-интеграция
этой установкой не меняется. Collaps прошёл проверку ссылок плеера.

## Ручной импорт

1. Найдите тайтл или вставьте внешние ID/ссылки в пакетный импорт (до 100 за запуск).
2. Откройте предпросмотр: изменения, источники, предупреждения и защищённые поля.
3. Выберите категории и дополнительные блокировки полей, поставьте импорт в очередь.
4. Проверьте журнал. Пауза/продолжение/повтор ошибочных элементов не сбрасывают
   успешно обработанные тайтлы. Отмена не удаляет уже импортированный контент.
5. Проверьте черновик в обычном редакторе и опубликуйте вручную.

Новые материалы всегда создаются **черновиками**. Обновление существующего не меняет
его публикацию. Совпадение определяется типизированными внешними ID (например,
TMDB movie и TV — разные пространства), а не названием. Конфликт ID останавливает
элемент; существующие материалы не объединяются автоматически.

Ручные изменения, включая очищенное поле, защищаются сравнением с последним
импортированным значением. Явные блокировки сохраняются на тайтле и добавляются
при последующих импортах; точный набор можно изменить в редакторе блокировок.
Неполные ответы провайдеров не удаляют серии и связи.
Внешние рейтинги не заменяют пользовательские оценки.

## Справочники и категории

Импорт создаёт/сопоставляет создателей, студии, жанры и доступные подборки по внешним
ID. Для людей без ID не используется опасное объединение только по имени.
Панель позволяет редактировать записи, вручную добавлять связи и роли. Публичные
страницы показывают только опубликованные тайтлы; приватные снимки источников и
правила категорий остаются административными данными.

Категории поддерживают иерархию и простые правила: тип, жанры, страны, диапазон
годов. Все заданные группы условий должны совпасть; внутри списка типов, жанров
или стран достаточно одного совпадения. `all` без дополнительных условий включает
все тайтлы. Правила применяются во время импорта;
изменение правила не запускает перерасчёт всего каталога. Ручные связи сохраняются.
Снятие связи в панели снимает ручную связь; импортированная связь может остаться.
Состав провайдерных подборок пополняется без автоматического удаления по неполной
странице источника. Полная зеркальная синхронизация состава — последующий этап.

## Расписания и подписки

Профили создаются выключенными. Доступны обновление метаданных существующих тайтлов,
обновление плееров/доступности и обход коллекции источника. Планировщик проверяет
профили каждые 5 минут; минимальный интервал профиля 15 минут. За запуск обрабатывается
до 100 тайтлов; сохранённый курсор продолжает обход на следующем запуске.
Новые тайтлы из коллекций также остаются черновиками.

Очередь `zalipImport` отделена от доставки ActivityPub. Прогресс хранится в
PostgreSQL; потерянные очередные задания восстанавливаются планировщиком.
Одновременные запуски одного задания/профиля сериализованы PostgreSQL advisory locks.
При 402/429 задание ставится на паузу с автоматическим повтором. Для Кинопоиска
Redis резервирует общий бюджет по ключу, проверяет остаток доступной квоты и
оставляет резерв 20 запросов; дополнительные приложения вне этого Redis не
учитываются локальным счётчиком. Все ключи Redis содержат только хеш ключа API.

Доступность Alloha/Collaps записывается в существующую систему событий и outbox
подписок. Первый импорт/первое установление исходной доступности не рассылает
старые серии; новые события у опубликованного тайтла используют обычную рассылку.
В этом этапе нет отдельного уведомления только по календарной дате премьеры
без появления доступности у провайдера.

## Проверка перед установкой

Сначала используйте отдельные PostgreSQL/Redis и тестовые ключи. Сделайте и
проверьте резервную копию. Две новые миграции:

- `1791667822000-ZalipCatalogDirectories.js`: справочники и связи.
- `1791668036800-ZalipImporterFoundation.js`: задания, профили, внешние ID,
  приватные исходные значения.

Проверьте миграции up/down/up и `pnpm --filter backend check-migrations` в
изолированной базе, затем HTTP e2e. Откат этих миграций удаляет журнал импорта,
сопоставления ID, блокировки и справочники; сами тайтлы остаются. Поэтому rollback
кода не заменяет восстановление базы из проверенной копии.

Проверьте один фильм и сериал каждого подключённого источника, затем пакет до
100 тайтлов. Обязательны проверки: отсутствие дублей; новые черновики; сохранение
ручного названия/описания; отсутствие доступа к панели у обычного аккаунта;
доступность обоих плееров; пауза/продолжение/отмена; уведомление только о новой
доступности, без повторов старых серий. Не включайте расписания до этих проверок.

Сборка и генерация SDK выполняются обычными командами проекта. Node должен
соответствовать engines и ABI установленных нативных модулей. На Windows текущий
`i18n generate` может не запустить генератор из-за сравнения пути; `pnpm --filter
i18n build --no-clean` генерирует типы и локали непосредственно.

Установка выполняется отдельно от локальной реализации: проверка резервной
копии, ORM-only прогон на изолированной базе, сборка неизменяемого релиза,
затем переключение приложения. Полный сервер на копии production-базы не
запускайте: существующие outbox/cron могут отправить повторные уведомления.
Проверки на моках не заменяют испытание реальных API и миграций.
