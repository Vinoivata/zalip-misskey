# Zalip subscription notification outbox

Catalogue and playback events remain in PostgreSQL. Dispatchers take a nonblocking shared dispatch claim and a per-event transaction-scoped advisory lock, then re-read its pending state inside that transaction. A busy claim skips the batch until the next tick instead of occupying the database pool with lock waiters while the winner packs notification recipients. The periodic tick attempts the two outboxes sequentially for fairness, including when import profiles are disabled. Active subscribers are checked again on every retry.

Native Misskey notifications are stored in Redis Streams, not a PostgreSQL notification table. For these outboxes, one Lua operation inserts the native notification and a permanent receipt scoped to event, recipient and notification type. A crash after the Redis insertion but before the PostgreSQL delivery acknowledgement can safely retry. Successful recipients are not inserted again after another recipient fails. Repeated delivery does not republish realtime events or push messages.

Receipts contain only the native stream ID; their keys are SHA-256 digests, not payloads, usernames or provider settings. They intentionally have no expiry and survive stream trimming and a user's notification flush. Do not delete receipt keys while the associated PostgreSQL event could be retried.

Redis persistence and backups must include both native notification timelines and `notificationReceipt:*` keys together. Restoring PostgreSQL and Redis from inconsistent snapshots can invalidate the deduplication guarantee; verify the selected persistence/backup policy operationally. Receipts have the same persistence and power-loss limitations as the native Redis notifications: an acknowledged write is not an additional disk-durability guarantee. This is idempotent insertion into the native Redis datastore, not a distributed exactly-once transaction between PostgreSQL and Redis. Realtime and push transport remain best-effort native behavior; a crash after storage can prevent an immediate realtime signal without losing the stored notification.
